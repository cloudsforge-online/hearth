Web wallet

One secp256k1 key, created in this tab, sealed with a passphrase you choose, and never sent anywhere. Balances and nonces are read over eth_* JSON-RPC from a Hearth node (same origin /rpc/ by default, override with ?rpc=); payments are signed on this device and broadcast already signed. There is no server-side wallet — if no node is reachable this page says so instead of inventing numbers.

This browser holds an Ed25519 key for an ember1… address, saved by the previous version of this wallet. It belongs to the pre-EVM chain and cannot be used here: an address on this chain is derived from a secp256k1 key by Keccak-256 (docs/evm-spec.md §2), and there is no way to turn one kind of key into the other. Nothing has been deleted: this wallet neither reads nor writes that record, and it is left exactly where it lies in case you want it for something else. The browser miner has moved to secp256k1 too, for the same reason — a block's coinbase has to be an account this chain can credit. Create a new key below.

Create or import a key

A wallet is one secp256k1 keypair. Creating one runs crypto.getRandomValues() in this tab — nothing is requested from the network and nothing about the key is sent anywhere. It is then sealed with AES-256-GCM under a key derived from the passphrase below by PBKDF2-HMAC-SHA256 at 600,000 iterations, and only the sealed form is written to this browser. The passphrase is never stored and cannot be recovered: forget it and the coins are gone, exactly as a lost backup file would be.

The same form MetaMask, cast wallet and Hardhat use, so a key works in all of them and here.

Your key

The private key is stored in this browser's localStorage under hearth.wallet.v3, sealed with AES-256-GCM under a key derived from your passphrase by PBKDF2-HMAC-SHA256 at 600,000 iterations. The passphrase is not stored anywhere, so a copy of this browser profile is not enough to spend these coins — and nobody, including us, can open the key for you if you forget it. What this wallet does and doesn't do

Does

Generates a secp256k1 key locally · derives an EIP-55 checksummed 0x address · seals the key at rest with AES-256-GCM behind a passphrase · reads balance and nonce over eth_* JSON-RPC · builds, signs (EIP-155, chain 7411) and broadcasts legacy type-0 transactions · decodes its own signed bytes back and refuses to send anything that does not recover to this address · polls for the receipt.

Doesn't

No mining (that is the miner) · no seed phrase or HD derivation — one key per browser · no passphrase recovery of any kind · no contract calls, no token transfers and no transaction data field · no EIP-1559 fees, because the chain has none in v1 (docs/evm-spec.md §3) · no hardware wallet · no complete history, for the reason given above the table.
